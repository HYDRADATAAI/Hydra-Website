SEVEN STAGES

One case, seven engineering decisions.

Each stage makes a different promise. The system does not blur source normalization, identity, authority, lineage, or interpretation into one opaque scoring step.

01

FRAGMENTED MARKET EVIDENCE

REPRESENTATIVE

Different source families arrive with different schemas and context. HYDRA keeps the observations separate rather than flattening them into one convenient narrative.

supplier_note: { supplier: "Apex Components", lead_time_days: 42 } issuer_extract: { issuer_alias: "Apex Comp.", capacity_note: "line constrained" } market_signal: { symbol: "APX", spot_move: "+11%", window: "5d" }
02

SOURCE NORMALIZATION

REPRESENTATIVE

Source-specific fields become a controlled evidence record without erasing source identity, time, or raw provenance.

evidence_id: ev_0184 source_ref: src_supplier_note_07 entity_alias: "Apex Components" claim_type: capacity_limit value: 42 unit: days raw_ref: raw/07#lead_time
03

IDENTITY RESOLUTION

REPRESENTATIVE

Aliases converge only when identity rules support the match. Identity resolution remains separate from deciding what the evidence means.

"Apex Components" ┐ "Apex Comp." ├─→ canonical_entity_id: ent_apex_001 "APX" ┘ identity_status: RESOLVED_REPRESENTATIVE
04

CONTRACT / AUTHORITY CHECK

REPRESENTATIVE + SHADOW PROOF

The downstream contract asks whether a required semantic value is actually owned or legitimately derivable, not whether a plausible value can be found nearby.

Discoverable data is not automatically authorized data.

AUTHORIZED PATHrequired field + valid owner/contract = ADMISSIBLE
BLOCKED PATHdiscoverable_data=YES
authorized_for_handoff=NO
result=BLOCK
fabricated_values=NO
05

PROVENANCE + HISTORY

REPRESENTATIVE

The admitted path keeps the source, evidence record, canonical entity, and constraint candidate linked. History adds context without overwriting the original observation.

src_supplier_note_07 ↓ ev_0184 ↓ ent_apex_001 ↓ cn_0042 ↺ source reference preserved ↺ history link preserved
06

CONSTRAINT INTERPRETATION

REPRESENTATIVE

The evidence supports a local bottleneck pattern. It does not justify upgrading the story into a systemic market shortage.

supported_scope: LOCAL classification: BOTTLENECK mechanism: CAPACITY / LEAD_TIME broader_shortage_claim: NOT_PROMOTED reason: evidence does not justify systemic scope
07

AUDITABLE RESULT

REPRESENTATIVE

The result carries both the conclusion and its evidence boundary. What the system declined to conclude remains visible.

constraint_id: cn_0042 entity_id: ent_apex_001 classification: local_bottleneck provenance_refs: [ev_0184, ev_0187] history_linked: true unsupported_claims: [systemic_shortage] status: REPRESENTATIVE_WALKTHROUGH

Visible source-to-result lineage

raw source fragment→evidence record→canonical entity→authority gate→history-linked candidate→bounded constraint result

The blocked branch stops at the authority gate. It does not silently jump forward to a populated downstream object.

VALID ENGINEERING OUTCOME: BLOCK

Missing authority is a reason to stop.

HYDRA located candidate data but could not prove authoritative ownership for the semantics required by the downstream handoff. The correct result was to refuse promotion. No substitute values were inferred from nearby data.

authority_source_status: MISSING required_semantics: NOT_PROVEN downstream_handoff: BLOCKED semantic_values_invented: false canonical_promotion: NONE classification: SHADOW
